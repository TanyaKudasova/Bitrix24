# Дашборд воронки продаж CRM

## Назначение и реализованные сценарии

Приложение встраивается в Битрикс24 отдельным пунктом левого меню и показывает аналитику по сделкам CRM текущего сотрудника. Работает от лица авторизованного пользователя и показывает только сделки, где он ответственный.

Реализованные сценарии.

1. Открытие из левого меню портала. Отдельная авторизация не нужна, токен сотрудника приходит из Битрикс24.
2. Ключевые показатели. Сумма открытых сделок, количество и сумма выигранных сделок за период, средний чек по выигранным.
3. Сводка по стадиям воронки. По каждой стадии количество сделок и сумма. Названия, порядок и семантика стадий берутся из `crm.status.list`.
4. Последние сделки. 15 последних сделок с названием, суммой, стадией и ответственным.
5. Фильтр периода. Сегодня, эта неделя, этот месяц, этот квартал, этот год, всё время и произвольный диапазон дат. Пустой или будущий период даёт нули без ошибки.

## Запрошенные скоупы

| Скоуп | Что даёт | Зачем нужен |
|---|---|---|
| `crm` | Чтение сделок и стадий | `crm.deal.list` для сводки и последних сделок, `crm.status.list` для названий стадий. Без него данных нет. |
| `user` | Профили сотрудников | `user.current` определяет открывшего дашборд, `user.get` даёт ФИО ответственных. |
| `placement` | Привязка мест встраивания | Регистрирует пункт `LEFT_MENU` в левом меню портала. |

Приложение только читает данные. Write-скоупы не запрашиваются.

## Известные ограничения

- Показываются только сделки, где текущий пользователь ответственный. Сделки коллег и подчинённых не видны.
- Приложение нужно открывать из портала. Прямой URL не знает, кто посетитель, и не может получить токен.
- Одна воронка, `CATEGORY_ID = 0`. Селектора дополнительных направлений нет.
- Суммы не приводятся к одной валюте. На мультивалютном портале итоги смешают валюты.
- Период считается по дате создания сделки, а не по дате закрытия.
- Выборка ограничена 5000 сделками. При превышении в интерфейсе появляется предупреждение.
- «Выигранные» определяются по системной стадии с семантикой `S`. «Открытые» это все стадии кроме успеха и провала.
- Нет кэша, экспорта и серверного хранилища. Каждый запрос читает CRM заново.

## Инструкция для проверяющего

1. Разместить `dash-001.php` по адресу из константы `APP_URL`. Значение должно совпадать с фактическим адресом.
2. Создать локальное приложение Битрикс24. Указать обработчик `https://www.maxreform.ru/files/app/tk/dash-001.php`, скоупы `crm`, `user`, `placement`.
3. Привязать место `LEFT_MENU`. Если у приложения есть скоуп `placement` и установку выполняет администратор, скрипт привяжет пункт сам. Иначе задать обработчик левого меню в карточке приложения.
4. Открыть приложение из левого меню портала. В шапке должен быть ФИО текущего сотрудника и подпись «Мои сделки».
5. Сверить KPI и таблицу по стадиям с фильтром CRM «Ответственный = текущий пользователь» за тот же период.
6. Переключить пресеты периода и задать произвольный диапазон. Задать пустой или будущий период, должны быть нули без ошибки.
7. Проверить список последних сделок. Название, сумма, стадия и ответственный должны совпадать с карточками CRM.
8. Открыть приложение под другим сотрудником. Набор сделок должен отличаться. Открыть под сотрудником без сделок, должны быть нули.

## Безопасность

- Запрашиваются только скоупы на чтение.
- Вебхуки не используются, токены не сохраняются.
- Все данные читаются токеном текущего сотрудника.
- Названия сделок, стадии и имена экранируются при выводе.
